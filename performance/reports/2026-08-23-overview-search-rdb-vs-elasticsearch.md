# 여행지 개요 검색 반영 후 RDB vs Elasticsearch 성능 비교

- 측정일: 2026-08-23
- 데이터: Gangwon Companion PostgreSQL `public` 스키마의 실제 수집 데이터
- 조건: 시나리오당 warm-up 5회, 측정 30회, 총 20개 시나리오
- 변경점: 여행지 검색 대상에 `destination_details.overview` 추가
- 원본 결과: `performance/results/live-rdb-vs-elasticsearch.json`

## 해석

`destination-keyword`에서 RDB가 763.519ms로 느려진 원인은 각 검색어마다 `destination_details.overview`를 확인하는 상관 `EXISTS` 서브쿼리가 수행되기 때문이다. ES는 개요가 포함된 `searchText`를 역색인하므로 같은 시나리오가 27.944ms로 약 27.3배 빠르다.

결과 일치율이 낮은 가장 큰 이유는 정책 필드가 없는 후보의 처리 방식 차이다. RDB는 반려동물·휠체어 정보가 `NULL`이면 `INSUFFICIENT_EVIDENCE` 상태로 후보를 유지하지만, ES는 해당 필드가 `true`인 문서만 필터링한다. 따라서 일부 정책 시나리오에서 RDB는 5건, ES는 0건을 반환했다. 이는 검색 성능 문제가 아니라 엔진 간 검색 계약 불일치다.

## 결론 및 권고

개요 기반 여행지 탐색에는 ES가 적합하다. 현재 데이터 규모에서도 개요 키워드 검색 p95가 RDB보다 약 27.3배 빠르다. 운영 전에는 다음 작업이 필요하다.

1. RDB와 ES의 `NULL` 정책 처리 계약을 통일한다.
2. 여행지 이름, 테마, 개요를 ES의 개별 필드로 분리해 가중치를 조정한다.
3. 개요 검색을 계속 RDB로 지원해야 한다면 PostgreSQL 전문검색 인덱스 또는 별도 검색용 컬럼을 도입한다.
4. 계약을 통일한 뒤 동일 시나리오로 결과 관련성과 성능을 다시 측정한다.
