검색엔진 비교 및 발전 계획

Gangwon Companion · 측정일 2026-08-22 · RDB/Elasticsearch 공통 검색 규칙 1차 적용

현재 실제 데이터 규모에서는 Elasticsearch의 결과가 있는 검색 평균 p95가 RDB보다 약 14.2% 빠르다. 하지만 엔진 선택을 확정할 핵심 근거는 속도보다 관련도다. 특히 오션뷰 펜션에서 두 엔진의 결과가 크게 달라 사람 판정 검색 정답 세트가 우선 필요하다.

3. 결과 해석

현재 판단: 지금 규모에서는 RDB도 충분히 빠르지만, 향후 한국어 관련도·필드 가중치·동의어·하이브리드 검색과 높은 동시성을 고려하면 Elasticsearch를 운영 검색엔진 후보로 유지하는 것이 타당하다. 최종 전환은 사람 판정 품질 평가 후 결정한다.

관련도 차이

바다 산책은 양쪽 모두 동일한 1건을 반환했다. 반면 오션뷰 펜션은 RDB 10건, ES 7건이며 Jaccard가 0.1333이다. LIKE 부분 문자열과 Nori 형태소 분석의 fallback 결과가 다르기 때문이다. 결과 개수나 RDB 일치율만으로 어느 쪽이 낫다고 판단할 수 없고 사람이 각 후보의 관련도를 판정해야 한다.

정책 필터

반려동물·크기·휠체어 값이 없는 문서는 엄격한 hard filter 결과에서 제외된다. 관련 시나리오 8개가 두 엔진 모두 0건이 된 것은 검색 오류가 아니라 현재 정책 데이터의 결측을 드러낸 결과다.

주의: 이번 벤치마크는 시나리오별 30회 순차 요청이다. 운영 결론에는 동시성 1·10·50, 시나리오별 300회, 3회 반복 측정이 추가로 필요하다.

4. 검색엔진 발전 로드맵

  1. 사람 판정 검색 정답 세트 구축
    실제 사용자 표현 50~100개를 모으고 후보별 관련도 0~3 등급을 부여한다. Precision@5, Recall@10, NDCG@10, zero-result rate, hard-filter violation rate를 자동 산출한다.
  2. 검색 문서 필드 분리
    현재 통합 searchText를 category, menuTypes, description, tags, policyText로 나눈다. 장소명 정확 일치 > 장소명 > 카테고리·메뉴 > 설명 > 주소 순으로 가중치를 조정한다.
  3. 도메인별 한국어 사전과 동의어
    오션뷰↔바다 전망, 애견↔반려견, 순두부↔초당순두부 같은 검증된 동의어를 관리한다. Nori 사용자 사전은 실제 실패 쿼리에서 확인된 복합명사만 추가한다.
  4. fallback 세분화
    2단어 쿼리에서 70%는 사실상 한 단어 일치다. 2단어는 구문·동의어 검색을 먼저 적용하고, 그 뒤 OR fallback을 쓰되 응답에 fallback 여부와 완화 단계를 기록한다.
  5. 정책 데이터 커버리지 개선
    Restaurant와 Lodging의 반려동물·휠체어 정보가 거의 없어 엄격 필터가 빈 결과를 만든다. 정책 필드별 true/false/null 비율을 지표화하고, 검증된 출처만 색인한다.
  6. 검색 관측성과 튜닝 루프
    익명화한 검색어, 필터, 결과 수, fallback 단계, 선택/클릭, 응답시간을 기록한다. zero-result와 재검색이 많은 쿼리를 주기적으로 정답 세트에 편입한다.
  7. 운영 규모 성능 검증
    동시성 1·10·50에서 300회씩 3회 반복하고 p50/p95/p99, 처리량, 오류율을 비교한다. 정책상 즉시 빈 결과가 되는 요청과 실제 검색 요청을 분리해 집계한다.
  8. 하이브리드 검색은 마지막에 검증
    BM25 기준선이 확정된 뒤 임베딩+kNN+RRF를 실험군으로 추가한다. NDCG@10 개선이 지연시간과 운영비 증가를 정당화할 때만 도입한다.
  9. CDC 기반 최신성 확보
    운영 전환 시 PostgreSQL을 원본으로 유지하고 Debezium CDC → Kafka → Search Indexer로 ES를 갱신한다. alias 재색인, DLQ, lag와 문서 수 불일치 알림을 함께 구축한다.
